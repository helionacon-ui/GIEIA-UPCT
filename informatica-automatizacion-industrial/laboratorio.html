Prácticas: el proyecto SCADA

En una frase

Las prácticas son un solo proyecto que se construye por fases a lo largo del curso, en grupo: una aplicación tipo SCADA en C++/Qt conectada a un PLC mediante OPC UA, con concurrencia, integración con ROS2 y módulos de análisis de datos e inteligencia artificial. Vale el 40 % y se cierra con una prueba individual de modificación de código.

Un orden de trabajo razonable

FaseQué hacerTema de la guía
1Proyecto Qt con CMake, ventana principal y layouts. Control de versiones con Git desde el primer día.T8, T9
2Conexión con el servidor OPC UA del PLC: conectar, recorrer el árbol, leer y escribir una variable.T7
3Suscripciones a las variables del proceso y HMI que se refresca sola, con alarmas según ISA-101.T7, T6
4Comunicación en un hilo aparte (worker + QThread) para que la interfaz nunca se congele.T10
5Registro de datos e histórico; gráficos de tendencia; cálculos sencillos (medias, anomalías).T14, T15
6Nodo ROS2 dentro de la aplicación o como puente: publicar datos del PLC en topics.T12
7Módulo de IA: informe de turno o asistente sobre los datos registrados, con validación humana.T15
8Memoria, vídeo de presentación del diseño y las funcionalidades.T11

Cómo preparar la prueba individual

  • Escribe tú al menos una parte de cada capa del proyecto (interfaz, comunicación, hilos), aunque el grupo se reparta el trabajo.
  • Lee el código de tus compañeros hasta poder explicar cada clase y cada connect.
  • Practica cambios pequeños con reloj: añadir una variable a la HMI, un límite de alarma, un slot nuevo, un campo en el registro.
  • Asegúrate de que sabes compilar el proyecto desde cero en el ordenador del laboratorio.

Lo que suspende

La prueba individual no compensa: si no se supera, la parte práctica queda suspensa aunque el proyecto sea excelente. Que el proyecto funcione no basta; tienes que poder modificarlo tú.

Estructura de ficheros recomendada

scada/
├─ CMakeLists.txt
├─ src/
│  ├─ main.cpp
│  ├─ mainwindow.h / .cpp / .ui     ← HMI
│  ├─ lectoropcua.h / .cpp          ← cliente OPC UA (en su hilo)
│  ├─ alarmas.h / .cpp              ← lógica de alarmas, sin widgets
│  ├─ registro.h / .cpp             ← histórico y exportación
│  └─ puenteros2.h / .cpp           ← nodo ROS2
└─ docs/                            ← memoria y diagramas UML

Separar la lógica (alarmas, registro) de la interfaz hace que cada parte se pueda probar y modificar por separado, que es justo lo que pide la prueba individual.
