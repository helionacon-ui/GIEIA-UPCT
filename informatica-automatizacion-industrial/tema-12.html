UD5 · Sistemas distribuidos y ROS2 · Tema 12

Sistemas distribuidos y ROS2

10 cuestionesUD5elaborado del programa

Desde cero

Objetivo: Explicar qué es ROS2, su arquitectura, nodos y paquetes, topics, servicios y acciones, QoS, la integración de sensores y actuadores, los gemelos digitales y la integración con Qt.

La idea

Un robot (o una célula automatizada) son muchos programas pequeños trabajando juntos: uno lee el láser, otro planifica, otro mueve los motores. ROS2 es el sistema que los conecta.

Cómo se hablan

Cada programa es un nodo. Los nodos publican y se suscriben a topics (flujos de datos), se piden cosas con servicios (pregunta-respuesta) y encargan tareas largas con acciones.

Por debajo

No hay un centro: los nodos se descubren solos gracias a DDS, un middleware de publicación/suscripción con calidad de servicio.

C++

#include <chrono>
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/float64.hpp"
using namespace std::chrono_literals;

// Nodo que publica el nivel de un tanque cada 500 ms en el topic /nivel
class PublicadorNivel : public rclcpp::Node {
public:
  PublicadorNivel() : Node("publicador_nivel") {
    pub_ = create_publisher<std_msgs::msg::Float64>("nivel", 10);    // depth 10
    timer_ = create_wall_timer(500ms, [this] {
      std_msgs::msg::Float64 msg;
      msg.data = leerNivel();
      pub_->publish(msg);
    });
  }
private:
  double leerNivel() { return 72.4; }          // aquí iría la lectura real
  rclcpp::Publisher<std_msgs::msg::Float64>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char **argv) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<PublicadorNivel>());
  rclcpp::shutdown();
}

Truco para acordarte

Truco topic/servicio/acción: el topic es la radio (emite sin saber quién escucha), el servicio es una llamada de teléfono (preguntas y esperas la respuesta) y la acción es un pedido a domicilio (encargas, te van informando y puedes cancelarlo).

Error típico

Llamar a ROS2 «sistema operativo». Es un framework y middleware que corre encima de Linux o Windows. Y conectar un publicador best effort con un suscriptor reliable: no se comunican.

Este tema no está en los apuntes: está elaborado a partir del programa oficial de la asignatura. Contrástalo con lo que se explique en clase.

Cuestión 98 añadida

¿Qué es ROS2?

✓Respuesta

ROS2 (Robot Operating System 2) no es un sistema operativo: es un framework y middleware de código abierto para construir aplicaciones de robótica. Aporta comunicación entre procesos, herramientas, bibliotecas y miles de paquetes ya hechos (navegación, visión, manipuladores).

Se publica en distribuciones; las de soporte largo son Humble Hawksbill (2022) y Jazzy Jalisco (2024). La documentación oficial está en docs.ros.org.

Cuestión 99 añadida

¿Qué mejora ROS2 respecto a ROS1?

✓Respuesta
  • Sin maestro central: ROS1 dependía de roscore; en ROS2 los nodos se descubren solos a través de DDS.
  • Calidad de servicio (QoS) configurable por comunicación.
  • Soporte para tiempo real y sistemas embebidos.
  • Seguridad (SROS2: autenticación y cifrado).
  • Multiplataforma: Linux, Windows y macOS.

Cuestión 100 añadida

Describa la arquitectura de ROS2.

✓Respuesta

Por capas, de arriba abajo:

  1. Nodos del usuario.
  2. Bibliotecas cliente: rclcpp (C++) y rclpy (Python).
  3. rcl: la biblioteca común en C.
  4. rmw (ROS middleware interface): la capa que abstrae el middleware.
  5. Una implementación de DDS (Fast DDS, Cyclone DDS).

Gracias a rmw se cambia de implementación DDS sin tocar el código.

Cuestión 101 añadida

¿Qué es un nodo y qué es un paquete en ROS2?

✓Respuesta
  • Nodo: la unidad de ejecución; un proceso (o parte de uno) que hace una sola tarea: leer un láser, calcular una trayectoria, mover un motor. Un robot es un grafo de muchos nodos.
  • Paquete: la unidad de organización y compilación. Contiene nodos, mensajes y ficheros de lanzamiento, con su package.xml y su CMakeLists.txt (C++) o setup.py (Python).

Los paquetes viven en un workspace (carpeta src) y se compilan con colcon build.

Cuestión 103 añadida

¿Qué es la calidad de servicio (QoS) en ROS2?

✓Respuesta

Son opciones que se fijan en cada publicador y suscriptor y que deben ser compatibles entre ellos:

  • Fiabilidad: reliable (se reintenta hasta entregar) o best effort (si se pierde, se pierde; ideal para sensores rápidos).
  • Historial: cuántos mensajes se guardan (depth).
  • Durabilidad: transient local guarda el último mensaje para los que se suscriben tarde; volatile no.

Un publicador best effort y un suscriptor reliable no se conectan: es un fallo típico.

Cuestión 104 añadida

¿Cómo se integran sensores y actuadores en ROS2?

✓Respuesta

Cada dispositivo tiene un nodo driver que traduce entre el hardware y los mensajes estándar:

  • Un sensor publica en un topic con un mensaje de sensor_msgs: LaserScan, Image, Imu, Temperature.
  • Un actuador se suscribe a un topic de órdenes, por ejemplo /cmd_vel con geometry_msgs/Twist para la velocidad de una base móvil.
  • Para controladores de motores se usa ros2_control.

Cuestión 105 añadida

¿Qué es un gemelo digital y qué herramientas de simulación usa ROS2?

✓Respuesta

Un gemelo digital es una réplica virtual de un equipo o una planta que se mantiene sincronizada con datos reales. Sirve para probar cambios, entrenar y detectar fallos sin tocar la instalación.

En ROS2 se usa Gazebo para simular el robot y su entorno con física (el mismo código funciona en simulación y en el robot real) y RViz para visualizar lo que el robot percibe.

Cuestión 106 añadida

¿Cómo se integra un nodo ROS2 en una aplicación Qt?

✓Respuesta

Las dos tienen su propio bucle de eventos, así que hay que conseguir que convivan:

  • Ejecutar rclcpp::spin() en un hilo aparte (QThread o std::thread), o
  • llamar a spin_some() periódicamente desde un QTimer en el hilo de la GUI.

Los callbacks del nodo no tocan la interfaz: emiten una señal Qt que llega en cola al hilo principal.
