UD3 · Programación · Tema 8

Programas, procesos y C++ orientado a objetos

8 cuestionesUD3elaborado del programa

Desde cero

Objetivo: Distinguir programa y proceso, saber cómo se compila un programa C++ y manejar clases, herencia, polimorfismo y memoria dinámica.

La idea

La aplicación SCADA del proyecto se escribe en C++. C++ es rápido y cercano al hardware, y permite organizar el código en clases: moldes que agrupan datos y funciones.

La orientación a objetos

Una planta se modela de forma natural con objetos: un Sensor, una Bomba, un Tanque. Cada uno guarda su estado y ofrece sus operaciones, y los sensores de distinto tipo se tratan igual gracias al polimorfismo.

La memoria

Lo que se crea con new hay que liberarlo. En C++ moderno no se hace a mano: se usan punteros inteligentes, que lo liberan solos.

C++

#include <iostream>
#include <memory>
#include <string>
#include <vector>

// Clase base abstracta: define la interfaz común de cualquier sensor
class Sensor {
public:
    explicit Sensor(std::string nombre) : nombre_(std::move(nombre)) {}
    virtual ~Sensor() = default;              // destructor virtual: obligatorio en una base
    virtual double leer() const = 0;          // virtual pura: la clase es abstracta
    virtual std::string unidad() const = 0;
    const std::string& nombre() const { return nombre_; }
private:
    std::string nombre_;                      // encapsulado: solo se lee con nombre()
};

class SensorTemperatura : public Sensor {
public:
    SensorTemperatura(std::string n, int crudo) : Sensor(std::move(n)), crudo_(crudo) {}
    double leer() const override { return crudo_ * 0.1; }        // décimas de grado
    std::string unidad() const override { return "°C"; }
private:
    int crudo_;
};

class SensorPresion : public Sensor {
public:
    SensorPresion(std::string n, int crudo) : Sensor(std::move(n)), crudo_(crudo) {}
    double leer() const override { return crudo_ / 1000.0; }     // de mbar a bar
    std::string unidad() const override { return "bar"; }
private:
    int crudo_;
};

int main() {
    std::vector<std::unique_ptr<Sensor>> planta;
    planta.push_back(std::make_unique<SensorTemperatura>("TT-101", 235));
    planta.push_back(std::make_unique<SensorPresion>("PT-201", 6150));
    for (const auto& s : planta)               // polimorfismo: cada uno lee a su manera
        std::cout << s->nombre() << " = " << s->leer() << " " << s->unidad() << "\n";
}                                              // unique_ptr libera la memoria solo (RAII)

Salida del programa (compilado y ejecutado con g++ en C++17): TT-101 = 23.5 °C y PT-201 = 6.15 bar. El bucle no sabe qué tipo de sensor tiene delante: el polimorfismo elige el leer() correcto.

Truco para acordarte

Truco de los cuatro pilares: «E-H-P-A», «El Hijo Puede Aprender»: Encapsulación, Herencia, Polimorfismo y Abstracción.

Error típico

Olvidar virtual en el método de la clase base: entonces s->leer() llama siempre a la versión de la base y el polimorfismo no funciona. Y olvidar el destructor virtual en una clase base.

Las cuestiones del tema, respondidas

Intenta contestar cada una antes de abrir la respuesta. Lo que va en negrita son las palabras que no pueden faltar.

Cuestión 66 añadida

¿Qué diferencia hay entre un programa y un proceso?

✓Respuesta
  • Un programa es algo estático: un fichero con instrucciones guardado en disco.
  • Un proceso es un programa en ejecución: tiene su memoria (código, datos, pila y montículo o heap), un identificador (PID), un estado y unos recursos asignados por el sistema operativo.

El mismo programa puede estar ejecutándose a la vez en varios procesos.

Cuestión 67 añadida

¿Cómo se pasa de un código C++ a un ejecutable?

✓Respuesta
  1. Preprocesador: resuelve #include, #define y la compilación condicional.
  2. Compilador: traduce cada fichero .cpp a código objeto (.o).
  3. Enlazador (linker): une los objetos y las bibliotecas en un ejecutable.

Por eso hay ficheros .h (declaraciones: qué existe) y .cpp (definiciones: cómo funciona). En Qt el proceso lo dirige CMake o qmake.

Cuestión 68 añadida

Defina clase y objeto.

✓Respuesta

Una clase es un molde: describe qué datos (atributos) y qué operaciones (métodos) tendrá algo. Un objeto es una instancia concreta de esa clase, con sus propios valores.

Ejemplo: la clase Bomba define caudal y arrancar(); bomba1 y bomba2 son dos objetos de esa clase.

Cuestión 69 añadida

¿Cuáles son los pilares de la programación orientada a objetos?

✓Respuesta
  • Encapsulación: los datos se ocultan (private) y solo se tocan a través de métodos (public). Así el objeto nunca queda en un estado incoherente.
  • Herencia: una clase derivada reutiliza y amplía otra base (class SensorPresion : public Sensor).
  • Polimorfismo: con funciones virtual, la misma llamada (s->leer()) hace lo que corresponde a cada tipo real de objeto.
  • Abstracción: se trabaja con interfaces (clases abstractas) sin depender de los detalles.

Cuestión 70 añadida

¿Qué son el constructor y el destructor?

✓Respuesta

El constructor es un método que se ejecuta al crear el objeto y lo deja en un estado válido; tiene el nombre de la clase y no devuelve nada. El destructor (~Clase()) se ejecuta al destruirlo y libera lo que el objeto tenga: memoria, ficheros, conexiones.

En una clase base el destructor debe ser virtual, para que al borrar un objeto derivado a través de un puntero a la base se llame también al destructor derivado.

Cuestión 71 añadida

¿Qué es una función virtual pura y una clase abstracta?

✓Respuesta

Una función virtual pura se declara con = 0 y no tiene implementación: obliga a las clases derivadas a definirla. Una clase con alguna función virtual pura es abstracta y no se pueden crear objetos de ella; sirve como interfaz común.

Cuestión 72 añadida

¿Qué diferencia hay entre pila (stack) y montículo (heap), y qué son los punteros inteligentes?

✓Respuesta
  • Pila: variables locales; se liberan solas al salir de la función. Rápida y limitada.
  • Montículo: memoria pedida con new, que dura hasta que se libera con delete. Si se olvida, hay una fuga de memoria.

Los punteros inteligentes (std::unique_ptr, std::shared_ptr) liberan la memoria solos cuando dejan de usarse. Es la idea RAII: el recurso se libera en el destructor. En C++ moderno no se escribe delete.

Cuestión 73 añadida

¿Qué diferencia hay entre pasar un parámetro por valor y por referencia?

✓Respuesta
  • Por valor (void f(Dato d)): la función trabaja con una copia; los cambios no salen fuera.
  • Por referencia (void f(Dato& d)): trabaja con el original; los cambios se ven fuera.
  • Por referencia constante (void f(const Dato& d)): sin copia y sin poder modificarlo. Lo normal para objetos grandes.
