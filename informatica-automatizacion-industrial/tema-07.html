UD2 · Supervisión y SCADA · Tema 7

OPC UA: comunicación con los PLC

7 cuestionesUD2elaborado del programa

Desde cero

Objetivo: Explicar qué es OPC UA, cómo organiza la información, qué servicios ofrece y por qué es la forma moderna de conectar un SCADA con un PLC.

La idea

Cada fabricante tiene su protocolo. OPC UA es el idioma común: cualquier cliente habla con cualquier servidor, y además sabe qué significa cada dato (unidad, rango, tipo).

Cliente y servidor

El servidor (por ejemplo dentro del PLC) publica un espacio de direcciones con objetos, variables y métodos. El cliente (la aplicación SCADA) lo recorre, lee, escribe y se suscribe a cambios.

Por qué importa en esta asignatura

El proyecto de prácticas conecta una aplicación C++/Qt con un PLC a través de OPC UA. Saber qué es un NodeId o una suscripción es la base para hacerlo funcionar.

Truco para acordarte

Truco de los tres tipos de nodo: los objetos son cosas, las variables son valores y los métodos son órdenes. Y el puerto, «48-40».

Error típico

Refrescar un HMI con lecturas cíclicas muy rápidas. Satura la red y aun así se escapan cambios. Lo correcto es una suscripción: el servidor avisa solo cuando algo cambia.

Cuestión 59 añadida

¿Qué es OPC UA?

✓Respuesta

OPC UA (Open Platform Communications Unified Architecture, norma IEC 62541) es un estándar de comunicación industrial independiente del fabricante y de la plataforma.

Sustituye al OPC clásico, que dependía de la tecnología COM/DCOM de Windows. OPC UA funciona en Windows, Linux o un PLC, y no solo transporta datos: transporta su significado (modelo de información).

Cuestión 60 añadida

¿Cómo se organiza la información en un servidor OPC UA?

✓Respuesta

En un espacio de direcciones (address space): una red de nodos unidos por referencias, que se recorre como un árbol de carpetas.

  • Objetos: agrupan cosas (Tanque1, Bomba2).
  • Variables: tienen un valor (Nivel, Temperatura) con su tipo, su calidad y su marca de tiempo.
  • Métodos: funciones que el cliente puede llamar (Arrancar, Resetear).

Cada nodo tiene un NodeId único: índice de espacio de nombres más identificador, por ejemplo ns=3;s="Tanque1"."Nivel".

Cuestión 61 añadida

¿Qué servicios ofrece OPC UA a un cliente?

✓Respuesta
  • Browse: recorrer el espacio de direcciones para descubrir qué hay.
  • Read y Write: leer y escribir atributos de nodos.
  • Call: ejecutar métodos.
  • Subscriptions con MonitoredItems: el servidor avisa solo cuando un valor cambia, sin que el cliente tenga que preguntar.

Cuestión 62 añadida

¿Qué diferencia hay entre leer cíclicamente y suscribirse en OPC UA?

✓Respuesta

Con lectura cíclica (polling) el cliente pregunta cada cierto tiempo, cambie o no el valor: mucho tráfico inútil y cambios rápidos que se escapan entre lecturas.

Con suscripción, el servidor muestrea la variable con un intervalo de muestreo y envía notificaciones solo cuando hay cambios, agrupadas cada intervalo de publicación. Menos tráfico y menos retraso. Es lo que hay que usar para refrescar un HMI.

Cuestión 63 añadida

¿Cómo protege OPC UA las comunicaciones?

✓Respuesta

Lleva la seguridad integrada en el protocolo:

  • Certificados X.509 para que cliente y servidor se autentiquen.
  • Tres modos: None (sin seguridad), Sign (firmado: no se puede alterar) y SignAndEncrypt (firmado y cifrado: tampoco se puede leer).
  • Autenticación de usuario con usuario y contraseña o certificado, y permisos por nodo.

Cuestión 64 añadida

¿Qué transporte y puerto usa OPC UA y cómo se conecta un PLC Siemens?

✓Respuesta

El transporte habitual es el binario sobre TCP, con direcciones del tipo opc.tcp://192.168.0.1:4840; el puerto por defecto es el 4840.

Los S7-1200 y S7-1500 llevan un servidor OPC UA que se activa en TIA Portal, donde se eligen las variables que se publican. La aplicación del proyecto actúa como cliente (en Qt, con el módulo Qt OPC UA y la clase QOpcUaClient).

Cuestión 65 añadida

¿Qué es OPC UA PubSub y cuándo se usa?

✓Respuesta

Es un modelo de comunicación añadido a OPC UA (desde la versión 1.04) en el que los publicadores envían datos sin conexión a los suscriptores, directamente sobre UDP o a través de un broker MQTT. Sirve para muchos receptores o para enviar datos a la nube, y combinado con TSN (Ethernet de tiempo sensible) para comunicación determinista entre controladores.
