UD3 · Programación · Tema 10

Concurrencia: procesos, hilos y tiempo real

9 cuestionesUD3elaborado del programa

Desde cero

Objetivo: Distinguir proceso e hilo, explicar condición de carrera, mutex, semáforo e interbloqueo, comprobar la planificabilidad de tareas de tiempo real y usar hilos en Qt.

La idea

Una aplicación industrial hace varias cosas a la vez: leer el PLC, guardar en la base de datos, refrescar la pantalla. Si todo va en un hilo, la pantalla se congela mientras se espera al PLC. Por eso se usan hilos.

El peligro

Los hilos comparten la memoria. Si dos tocan el mismo dato a la vez, el resultado depende de la suerte: es una condición de carrera. La solución es proteger ese trozo con un mutex.

Tiempo real

En control no basta con ser rápido: hay que cumplir plazos, siempre. Con prioridades fijas, una cuenta sencilla (la utilización) dice si las tareas caben.

C++

#include <iostream>
#include <mutex>
#include <thread>

long contador = 0;
std::mutex m;

void sumarSinProteger(int n) { for (int i = 0; i < n; ++i) ++contador; }
void sumarProtegido(int n) {
    for (int i = 0; i < n; ++i) {
        std::lock_guard<std::mutex> cerrojo(m);   // se libera solo al salir del bloque
        ++contador;
    }
}

int main() {
    const int N = 1000000;
    std::thread a(sumarSinProteger, N), b(sumarSinProteger, N);
    a.join(); b.join();
    std::cout << "sin mutex: " << contador << " (esperado " << 2 * N << ")\n";
    contador = 0;
    std::thread c(sumarProtegido, N), d(sumarProtegido, N);
    c.join(); d.join();
    std::cout << "con mutex: " << contador << "\n";
}

Salida real de este programa en una ejecución: sin mutex: 1091154 (esperado 2000000) y con mutex: 2000000. Sin protección se pierde casi la mitad de los incrementos, y el número cambia cada vez.

Truco para acordarte

Truco para el interbloqueo: las cuatro condiciones de Coffman, «Mi Reloj Siempre Espera»: Mutua exclusión, Retención y espera, Sin expropiación, Espera circular. Quita una y no hay interbloqueo.

Error típico

Creer que contador++ es una sola operación. Son tres (leer, sumar, escribir), y entre ellas otro hilo puede colarse. Y en tiempo real, confundir rápido con determinista.

Este tema no está en los apuntes: está elaborado a partir del programa oficial de la asignatura. Contrástalo con lo que se explique en clase.

Cuestión 81 añadida

¿Qué diferencia hay entre un proceso y un hilo?

✓Respuesta
ProcesoHilo
MemoriaPropia y aisladaCompartida con los demás hilos del proceso
Coste de crear y cambiarAltoBajo
ComunicaciónMecanismos del SO (tuberías, sockets, memoria compartida)Directa, a través de variables comunes
Si fallaNo afecta a otros procesosPuede tumbar todo el proceso

Un hilo es una línea de ejecución dentro de un proceso. Un proceso tiene al menos un hilo.

Cuestión 82 añadida

¿Cuáles son los estados de un proceso?

✓Respuesta
  • Nuevo: se está creando.
  • Listo: puede ejecutarse y espera su turno de CPU.
  • En ejecución: está usando la CPU.
  • Bloqueado: espera algo (E/S, un mutex, un temporizador).
  • Terminado.

El planificador decide qué proceso listo pasa a ejecución.

Cuestión 83 añadida

¿Qué es una condición de carrera y cómo se evita?

✓Respuesta

Ocurre cuando dos hilos acceden a la vez a un dato compartido, al menos uno escribe, y el resultado depende del orden en que se intercalan. Ejemplo: dos hilos hacen contador++, que en realidad es leer, sumar y escribir; si se intercalan, se pierden incrementos.

Se evita con exclusión mutua: el trozo de código que toca el dato (sección crítica) se protege con un mutex, de modo que solo un hilo puede estar dentro.

Cuestión 84 añadida

¿Qué es un mutex y qué es un semáforo?

✓Respuesta
  • Mutex: cerrojo con dos estados. El hilo que lo bloquea es el único que puede entrar en la sección crítica y debe liberarlo. En C++ std::mutex con std::lock_guard; en Qt QMutex con QMutexLocker.
  • Semáforo: un contador. Deja pasar a N hilos a la vez y bloquea al siguiente. Sirve para limitar el acceso a N recursos o para avisar entre hilos (productor-consumidor).

Cuestión 85 añadida

¿Qué es un interbloqueo (deadlock) y cuándo ocurre?

✓Respuesta

Dos o más hilos se quedan esperando para siempre porque cada uno tiene un recurso que el otro necesita. Hacen falta las cuatro condiciones de Coffman a la vez:

  • Exclusión mutua: el recurso no se comparte.
  • Retención y espera: se retiene uno mientras se espera otro.
  • Sin expropiación: nadie puede quitarle el recurso a un hilo.
  • Espera circular: A espera a B y B espera a A.

La solución más práctica: pedir siempre los cerrojos en el mismo orden.

Cuestión 86 añadida

¿Cómo se crean hilos en una aplicación Qt?

✓Respuesta

La forma recomendada es el patrón worker: se escribe una clase que hereda de QObject con el trabajo pesado en un slot, se crea un QThread y se mueve el objeto a ese hilo con moveToThread(). El worker comunica sus resultados con señales, que llegan en cola al hilo de la GUI.

C++

auto *hilo = new QThread;
auto *lector = new LectorOpcUa;           // QObject con el trabajo pesado
lector->moveToThread(hilo);
connect(hilo, &QThread::started, lector, &LectorOpcUa::trabajar);
connect(lector, &LectorOpcUa::nuevoValor, this, &MainWindow::mostrar);  // llega en cola
hilo->start();

Cuestión 87 añadida

¿Qué es un sistema de tiempo real? Diferencie tiempo real duro y blando.

✓Respuesta

Un sistema en el que un resultado solo es correcto si llega dentro de su plazo (deadline).

  • Tiempo real duro: incumplir un plazo es un fallo (airbag, control de un eje, parada de emergencia).
  • Tiempo real blando: incumplirlo degrada el servicio pero no es catastrófico (refresco de un HMI, vídeo).

Cuestión 88 añadida

¿Cómo se comprueba si un conjunto de tareas periódicas cumple sus plazos con prioridades fijas?

✓Respuesta

Con planificación Rate Monotonic (más prioridad a la tarea de periodo más corto) y la prueba de Liu y Layland: si la utilización total cumple

U = Σ Ci/Ti ≤ n·(21/n − 1)

todas las tareas cumplen sus plazos. C es el tiempo de cómputo, T el periodo y n el número de tareas. El límite vale 1 para una tarea, 0,828 para dos, 0,780 para tres y tiende a 0,693. Es una condición suficiente: si no se cumple, puede que aún sea planificable, y hay que comprobarlo con el análisis de tiempos de respuesta. Si U > 1, seguro que no lo es.

Cuestión 89 añadida

¿Cómo se comunica una aplicación C++/Qt con los dispositivos industriales?

✓Respuesta
  • Puerto serie: QSerialPort (RS-232/RS-485).
  • TCP/UDP: QTcpSocket, QUdpSocket.
  • Modbus: QModbusTcpClient y QModbusRtuSerialClient (módulo Qt Serial Bus).
  • CAN: QCanBus.
  • OPC UA: módulo Qt OPC UA.

Todas estas clases son asíncronas: se pide la operación y el resultado llega con una señal (readyRead, finished), así la interfaz nunca se congela.
